# 我的电视 · 整体测试计划

> 目的：在"优化与简化体验、提高稳定性"的迭代开始前，先建立一套可重复执行的验证基线，
> 用测试结论决定改什么，而不是凭感觉改。

## 一、现状与前提

| 项 | 现状 |
|---|---|
| 版本 | v2.1.0（`versionCode` 由 git tag 推导） |
| 兼容 | `minSdk 21`（Android 5.1）→ `compileSdk 34` / `targetSdk 33` |
| 自动化测试 | **完全没有**：`app/src` 下只有 `main`，无 `test` / `androidTest` |
| 构建 | `release` 未开 `minify` / `shrinkResources` |
| 使用形态 | 遥控器为主 + 手机浏览器远程配置为辅 |

因此本计划采用 **「人工为主 + adb 脚本辅助」** 的方式落地，并逐步把可自动化的断言沉淀成脚本。

### 可用的可观测手段（测试时就靠这些取证）

| 手段 | 内容 |
|---|---|
| logcat tag | `TVList` `ChannelProbe` `LineHealth` `MainActivity` `MainFragment` `PlayerFragment` `Request` `EpgStore` `ChannelFragment` `InfoFragment` `SettingFragment` |
| 设备内文件 | `files/channels.json` `probe.json` `line_health.json` `epg_cache.json` `crash/` |
| adb | `screencap` / `uiautomator dump` / `input keyevent` / `run-as cat` |
| 远程配置 | `http://<ip>:34567/?token=xxxxxx` 的 `/api/config` `/api/test` `/api/save` |

## 二、环境矩阵

| 维度 | 取值 | 说明 |
|---|---|---|
| 设备 | MuMu 模拟器 | 触屏环境，D-pad 焦点行为与真机不同（触屏模式下 Button 不获焦），**仅用于功能验证，不代表遥控器体验** |
| 设备 | 真机 TV / 盒子（用户持有） | **按键、解码、长稳的唯一可信环境** |
| 系统 | Android 5.1 / 7 / 9 / 11 / 14 | 至少覆盖 minSdk 下限、一台老盒子、一台新 TV |
| 输入 | 遥控器 D-pad / 鼠标 / 触屏 / 手机浏览器 | 长按类操作在不同遥控器上重复率差异大 |
| 网络 | 有线 / WiFi / 断网 / 弱网(限速) / GitHub 直连失败(需镜像) / IPv6-only | 弱网用 `adb shell` 无法模拟，需路由器侧限速 |
| 显示 | 1920x1080 / 1280x720 / 4:3 老电视 / 异常 DPI | 画面比例与信息条布局 |

## 五、稳定性专项

| 专项 | 方法 | 通过标准 |
|---|---|---|
| 长稳播放 | 单频道连续播放 ≥ 4h（建议 12h） | 无崩溃/ANR；内存无持续增长；画面不卡死 |
| 反复切台 | 连续上下切台 200 次 | 无崩溃；每次都能出画面或明确失败提示 |
| 反复切线路 | 连续左右切线路 100 次 | 无崩溃；播放器实例不泄漏 |
| 反复开关列表 | OK 键连续 100 次 | 焦点正常，无空指针 |
| 网络扰动 | 飞行模式开关 ×20，间隔 15s | 恢复后自动重连播放 |
| Monkey | `adb shell monkey -p com.lizongying.mytv --throttle 300 -v 20000` | 无崩溃（日志中无 `FATAL EXCEPTION`） |
| 内存基线 | `adb shell dumpsys meminfo com.lizongying.mytv` 记录启动/1h/4h | 增长 < 50MB 且趋于平稳 |
| 后台驻留 | 切后台放置 2h 后回前台 | 正常恢复播放 |

## 六、回归清单（每次改动必测，10 条）

1. 冷启动（有缓存）秒开并起播
2. 离线启动可用（缓存/内置源）
3. 换源后原地重载、不重建 Activity
4. 上下切台 + 数字选台（1/2/3 位）
5. 短按左右切线路，信息条显示线路序号
6. 长按左右打开线路列表，能选中并切换
7. 长按 OK 收藏，播放不中断
8. 远程配置保存后即时生效
9. 切后台回前台恢复播放
10. BACK 逐级返回与退出

## 七、自动化沉淀方案

| 可自动化 | 断言方式 |
|---|---|
| 启动到首帧时间 | 计时 + 截图关键帧 |
| 源加载结果 | `logcat -s TVList` 断言 `remote sources merged: N/M` |
| 探活范围 | `logcat -s ChannelProbe` 断言 `probed N lines` 的 N 区间 |
| 缓存生成 | `run-as ls files` 断言 4 个 json 存在 |
| 切台成功率 | 连续按键 + 截图变化检测 |
| 崩溃检测 | `logcat | grep FATAL EXCEPTION` |

建议沉淀为 `tools/verify.ps1`（PowerShell + adb，Windows 上可直接跑），
把上面这套已经在用的 adb 手法固化下来，避免每次手工拼命令。

**必须人工的**：画质/花屏/卡顿判断、遥控器手感、不同盒子的解码兼容。

## 八、缺陷记录规范

每条缺陷需包含：

1. 用例 ID + 复现步骤（精确到按键）
2. 环境（设备型号 / Android 版本 / 网络）
3. 取证：相关 tag 的 logcat 片段 + 截图
4. 崩溃类：`adb shell run-as com.lizongying.mytv ls files/crash` 后拉取对应文件
5. 影响面判断：是否主流程阻断、是否有临时绕过手段
