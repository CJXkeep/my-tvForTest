# 我的电视 · 迭代计划（体验简化 + 稳定性）

> 本文是 `docs/测试计划.md` 的后续：先用通读代码定位**确定的**问题，
> 再用测试计划里的用例去验证，最后按优先级排迭代。
> 原则不变：**大道至简、不把操作抛给用户、数据源做到极致。**

## 二、方向判定

测试计划覆盖了 12 个模块、约 60 条用例，其中**主流程阻断项（P0）集中在三处**：

1. **选台能力不完整**（E1/E2）——数字选台在 2442 个频道里只能覆盖前 99 个，属于"功能名义存在但实际不可用"。
2. **高频操作代价过大**（E3）——收藏是最常用的正向操作之一，却触发全量重载 + 重播。
3. **异常防御不足**（E4/E5/E6）——NPE 风险、时钟漂移、常驻服务，都是"偶发但难查"的稳定性问题。

再加上一批"不符合大道至简"的残留（E7/E11/E12）。
因此新迭代分三个批次：**先修体验硬伤 → 再补稳定性 → 最后工程收尾**。

## 三、迭代 A：体验简化（P0，优先做）

目标：**能用的地方不需要说明书，也不需要设置。**

### A1 数字选台支持 3~4 位

- 现状：`ChannelFragment` 只允许 2 位数字，且第 3 位被直接丢弃。
- 改法：
  - 允许最多 4 位；输入过程中只显示数字，不跳台；
  - 超时统一为 **2 秒无输入即跳台**（当前 1 位等 3s、2 位立即跳，体验割裂）；
  - 位数达到 4 位或超时即跳。
- 验收：`ZAP-03/04/07` 通过；连按 `1``0``1` 跳 101 号台；按 `9999` 提示"频道不存在"。
- 风险：习惯"2 位立即跳"的用户手感变化 → 通过统一为 2s 超时保持一致预期。

### A2 收藏不打断播放

- 现状：收藏 → `reloadChannels()` → 重新拉网络 + 重新探活 + `restorePosition()` 重播。
- 改法：收藏只做**本地重排**——把收藏频道移到「★收藏」分组、重算编号、就地更新列表，
  **不发起网络请求、不重新 prepare 播放器**。
  - 具体：给 `MainFragment` 增加 `refreshFavoritesOnly()`，只重建 adapter 数据与编号，
    不调用 `TVList.load()`、不调用 `changed()`。
- 验收：`FAV-01/02` 通过；长按收藏后**画面零重缓冲**，收藏项立刻置顶。
- 风险：收藏分组位置变化时的选中态恢复 → 按频道名回定位（已有 `restorePosition` 可复用）。

### A3 设置页再减法

- 现状（5 个可点项）：保存并重新加载、恢复默认源、恢复默认设置、退出、两个开关。
- 改法：
  - **删「退出」**：BACK 两次已可退出，按钮冗余；
  - **「恢复默认设置」移到远程配置页**（低频、且本就更适合在手机上点）；
  - 保留：显示时间、开机自启、数据源（保存 / 恢复默认源）、远程配置地址。
- 验收：`SET-05`；设置页可点项 ≤4，遥控器 3 次以内可到达每一项。
- 风险：老用户找不到"恢复默认设置" → 在远程配置页明确标注，并在文档说明。

### A4 信息条不折行 + 文案统一

- 现状：`CCTV-1 综合 线路 2/8` 折成两行。
- 改法：信息条固定单行 + `ellipsize="end"`；线路提示统一为「频道名 · 线路 N/M」。
- 验收：`LINE-01` 在 1080p/720p 下均单行显示。

### A5 首次引导合并为一次

- 现状：远程配置引导与手势提示分两次、间隔 6 秒，第二条容易被错过。
- 改法：合并为一条（换行展示），只在真正首次启动出现一次。
- 验收：`BOOT-06`；清数据后启动只见一次提示。

## 四、迭代 B：稳定性加固（P0/P1）

目标：**把"偶发打不开/莫名崩溃"消掉。**

### B1 消除 `!!` 风险（E4）

- 改法：`getVideoUrlCurrent()` 改为返回 `String?` 或返回空串并让调用方短路；
  `firstSource()`/`addVideoUrl()` 判空；在 `resetSourceTypes()`、`play()` 入口加空线路保护。
- 验收：`ERR-05`；构造"全线路被屏蔽"的源不崩溃、不黑屏，进入明确报错分支。
- 风险：改动点在播放主链路 → 必须配 `PLAY-01/02/03` 回归。

### B2 数字输入状态随生命周期重置（E2）

- 改法：`ChannelFragment.onPause()` 同时清空 `channel`/`channelCount`（或超时后再跳台）。
- 验收：`ZAP-05`。

### B3 时钟同步加固（E5）

- 改法：`between` 加 `@Volatile`；同步从"仅启动一次"改为 **启动 + 每 6 小时（及网络恢复时）校准**。
- 验收：`EPG-05`；把设备时间手动改错 10 分钟后启动，EPG 与显示时间仍正确。
- 风险：校准有网络开销 → 失败静默、不阻塞、不提示。

### B4 配置服务按需启停（E6）

- 改法：改为**惰性启动**——仅当用户在设置页查看/需要远程配置时启动；
  或启动后在 N 分钟无请求自动 `stop()`，下次进入设置页再启动。
- 验收：`WEB-06`；不在设置页停留时，`netstat` 看不到 34567 监听。
- 风险：用户扫旧地址打不开 → 设置页打开即启动，地址不变。

### B5 长按判定改为时间戳（E8）

- 改法：用 `event.eventTime/SystemClock` 判定"按下超过 500ms"，替代 `repeatCount`。
- 验收：`KEY-01/02/03`；至少两种遥控器手感一致。
- 前提：**先真机验证** E8 是否真实存在，若当前遥控器无问题，可降级为 P2。

### B6 崩溃日志可在浏览器导出

- 改法：远程配置页加"查看崩溃日志"（读 `files/crash/` 最近一份）。
- 验收：`ERR-01`；用户能直接把崩溃堆栈发给开发者。
- 风险：暴露设备信息 → 仅在有 token 的页面展示。

## 七、明确不做

- 不新增需要用户手动配置的开关（设置项只会更少，不会更多）。
- 不新增"多播放列表 / 频道分组管理 / 自定义主题"等偏管理向的功能。
- 不引入需要维护的服务端或账号体系。
- 不做绕过平台鉴权/付费墙的内容接入（延续既有边界）。

## 八、执行方式

每个迭代项都按同一节奏走：

1. 先按测试计划对应用例**复现并确认**（尤其是标"待实测"的项）；

3. 在模拟器验证功能，**在真机验证手感/解码**；
4. 跑第六节的 10 条回归清单；
5. 更新 `docs/设计与迭代计划.md` 的进度记录。

> 没有真机时，第 3 步的手感/解码项记为"未验证"，**不得视为通过**。

## 十、追加改造：编号统一 + 左侧列表选台（按用户反馈）

### 起因

用户在真机看到列表后提出两点：

1. **数字编号这块有两套**——源里的 `tvg-chno` 与列表序号混用，会出现"信息条显示 5，按 5 却跳到别的台"。
2. **选台不该做成整屏大面板**，改成左侧列表更方便（右侧能继续看到画面）。

### 决策（已与用户确认）

- 编号**只保留一套**：列表序号（`tv.id + 1`）。源里的 `tvg-chno` 不再参与显示与选台。
- **移除收藏功能**（连带释放长按 OK 的收藏手势）。
- 选台改为**左侧竖排列表**：占屏约 1/3，右侧保留播放画面，分组名做分节标题。

### 改动清单

| 区域 | 改动 |
|---|---|
| 新增 | `ChannelListAdapter`（分组标题 + 频道行）、`main_list.xml`、`item_channel_list.xml`、`item_group_header.xml`、`list_item_bg.xml` |
| `MainFragment` | 从 Leanback `BrowseSupportFragment` 重写为普通 `Fragment` + `RecyclerView`；播放 / 切台 / 探活 / EPG 逻辑原样保留 |
| 键位 | 播放中：上下切台、左右切线路、OK 开关列表、**长按 OK 打开线路列表**（原长按左右取消）；列表打开：上下移动选择、OK 切台并收起、**左右切换分组**（原右键"打开设置"取消） |

| 收藏移除 | `TVList` 的 `applyFavorites`/`reorderByFavorites`/`matchFavorite`/`toggleFavorite`、`SP.favorites`、远程配置页收藏输入框、`/api/config` 与 `/api/save` 的收藏字段 |

## 十一、频道白名单：只保留央视 + 主流地方卫视

### 起因

用户反馈聚合源里混入大量游戏直播（斗鱼/虎牙）、购物、地方城市台，"太多了没有用"，要求只保留央视与主流地方卫视。

### 实现

`TVList.isWanted()` + `applyChannelFilter()`，在 `finalize()` 归一化阶段**先过滤再折叠**（避免白做工）：

| 类别 | 规则 |
|---|---|
| 央视 | `CCTV_KEEP` 白名单：`CCTV-1~17`、`CCTV-5+`、`CCTV`（归一化后失去台号的如 CCTV-4K） |
| CGTN / 凤凰卫视 | 明确保留 |
| 地方卫视 | 归一化名 `endsWith("卫视")`（湖南卫视、东方卫视、海峡卫视…） |

两个刻意的选择：

- 用 `endsWith("卫视")` 而不是 `contains`——否则"北京卫视养生堂"这类**节目名条目**会被当成频道留下。
- **安全阀**：过滤后一个不剩时（例如用户配的是纯地方台源）保留原样，避免给用户一个空列表。

调整保留范围只需改 `CCTV_KEEP` 与 `isWanted` 两处。

### 实测结果

```
channel filter: keep 67, drop 2395        ← 2462 → 67 台
列表：央视频道（CCTV-1 综合 正在播放 / 2 财经 / 3 综艺 / 4 中文国际 / 5 体育 / 5+ 体育赛事 / 6 电影 …）
      卫视、纪录频道等共 3 个分组
```
「斗鱼」「虎牙」「购物」等杂项分组整体消失。

### 连带修复的三个问题

1. **缓存大小保护失效**：原逻辑是"新列表不足旧的一半就不落盘"。开了白名单后新列表必然远小于旧缓存，缓存将永远无法更新。已改为**按白名单内频道数比较**。
2. **越界位置夹到最后一条**：列表从 2462 缩到 67 后，保存的位置 483 越界被 `coerceIn` 夹到末尾，结果默认播了一个莫名其妙的频道。已改为**越界回到第一台**（CCTV-1）。
3. **残缺列表覆盖完整列表**：部分订阅源失败时（实测 1/3 或 2/3 成功）会拿到残缺列表，直接覆盖会让用户看到"频道凭空少一半"。已增加 `TVList.lastLoadComplete` + 数量比较：**残缺列表只有在不比当前更少时才采用**，下次全部成功再刷新。实测 `incomplete (42 < 67), keep current` 生效，列表不再越刷越少。

### 未改动

默认订阅源**保持原样**：从 PC 验证三个源均返回 200，日志中的失败来自模拟器网络（`raw.githubusercontent.com` 在国内不稳定），不是源失效。

### 待观察

- 部分 CCTV 频道显示"暂不可用"，是源里这些频道的线路本身全部失败（已由 `LineHealth`/`ChannelProbe` 标记）。真机网络环境下可用率应更高，需要真机复验后再决定是否补充源。

## 十二、选台面板改为两级：分组 → 频道

### 起因

用户看了"单列 + 分节标题"的列表后提出"应该是分组先的"，确认为**先选分组、再选频道**的两级结构。

### 改动

| 区域 | 改动 |
|---|---|
| 布局 | `main_list.xml` 改为两列（左 112dp 分组列 + 右频道列）；新增 `item_group_list.xml`；`item_channel_list.xml` 收窄（行高 52dp、编号列 38dp） |
| 新增 | `GroupListAdapter`：分组名 + **▶ 标记正在播放的分组** |
| 简化 | `ChannelListAdapter` 去掉分节标题行，只渲染当前分组的扁平列表，另加焦点回调 |
| `MainFragment` | `showGroup()` 切右列、`moveFocus()` 列间移动、`onGroupFocused()` 驱动补探；编号仍为全局列表序号 |
| `MainActivity` | 面板打开时左右键改为列间移动（替换原先"左右直接切分组"的实现） |

### 关键发现：原生焦点搜索不跨列

两列都是 `RecyclerView`，横向的 `focusSearch` 不会自己跨到另一列（实测按右键毫无反应）。
因此左右键改为**显式控制**（`MainFragment.moveFocus()`），而不是依赖系统行为——更可靠，也顺便去掉了原先"左右键切分组"的临时做法。

### 实测结果（模拟器）

| 操作 | 结果 |
|---|---|
| 打开面板 | 焦点落在分组列（当前分组），右列显示该分组，▶ 标记播放中的分组 |
| 分组列上下 | `focusGroup 0 → 1`，右列跟着换成「卫视频道 · 26 台」 |
| 右键 | `focusChannel 15`（该分组第一条）——焦点进入频道列 |
| 频道列上下 | `focusChannel 15 → 16` |
| OK | `chosen 16` → `switch 东方卫视`，面板收起并起播 |

### 连带修复

**缓存写入判定与界面侧不一致**：界面侧规则是"残缺且更少才拒绝"，而缓存写入用的是"不足旧的一半才拒绝"（宽松得多），
结果一次部分失败的加载把缓存从 67 台写成了 42 台，下次启动直接渲染 42 台。
已统一为：**加载完整就写；不完整时只有不少于旧缓存才写**。

另：频道列增加焦点回调，浏览频道时同样会重置自动收起计时（原先只有切分组才重置）。

### 待真机确认

- 两列宽度（112dp + 228dp）与字号在 1080p 真机上的观感。

## 十三、面板不再自动收起 + 分组重整

### 面板只在「选中频道」或「返回」时关闭（用户要求）

- 移除面板的自动收起定时器：删掉 `mainActive()`、`hideMain` Runnable 与 `delayHideMain`，
  以及 `switchMainFragment()` / `onResume()` / `onPause()` 里的相关调度；`MainFragment` 中两处调用一并移除。
- 关闭入口保留两个：**OK 选中频道**（`hideListAndPlay()`）与**返回键**（`back()` 先关面板、再退出）。
- 实测：打开面板后 20 秒不操作，面板仍保持打开 ✓

> 设置弹窗仍保留 10 秒自动收起（`delayHideSetting`）——用户未提及，未改动。

### 分组重整：只留「央视频道 / 卫视频道」

**起因**：实测发现直播源自己的分组名名不副实——「咪咕央视」里装着 CGTN纪录/海峡卫视，
另外还有「备用频道」「港澳代理」「港澳频道」「内蒙古频道」等分组，与实际内容对不上。

**改动**（`TVList.applyChannelFilter`）：

- 白名单过滤后按规则重新归入两个分组：`CCTV*` / `CGTN*` → **央视频道**；其余（X卫视、凤凰卫视）→ **卫视频道**
- **央视按台号排序**：`CCTV5 → 50`、`CCTV5+ → 51`、`CCTV12 → 120`，无台号的（如 CCTV-4K）排最后
- 同步改写 `TV.channel` 字段，保证"当前频道属于哪个分组"的判断仍走快路径

**实测**：3/3 源全部成功 → `keep 181 (cctv=68, sat=113), drop 2622` → 折叠同名频道后 **2 个分组 / 79 台**。
界面效果：

```
分组          央视频道 · 27 台
▶央视频道      1 CCTV-1 综合     正在播放
 卫视频道      2 CCTV-2 财经     暂不可用
               3 CCTV-3 综艺
               4 CCTV-4 中文国际
               5 CCTV-5 体育
               6 CCTV-5+ 体育赛事
               7 CCTV-6 电影
               8 CCTV-7 国防军事 暂不可用
```

**回退方式**：把 `applyChannelFilter` 里的分桶逻辑改回"沿用源的分组名"（`kept[group]`）即可。

### 设置入口（用户反馈"设置页面要怎么打开"）

**背景**：把"面板打开时按右键进设置"改成"左右键切列"后，原本习惯的入口消失了。

**现在共有三个入口**：

| 入口 | 说明 |
|---|---|
| 遥控器 `MENU` 键 | 部分遥控器映射为 帮助 / 设置 / 书签 键，这几种也都能打开（`KEYCODE_MENU/HELP/SETTINGS/BOOKMARK/UNKNOWN`） |
| 触屏双击 | `GestureDetector.onDoubleTap` |
| **面板 → 分组列末尾「设置」** | 新增：不依赖任何特殊按键，OK 打开面板后一直往下按即可到达 |

**实现要点**：这个「设置」项必须放在 `GroupListAdapter` **列表内部**（作为最后一项）。
最初把它作为列表外的固定行放在布局底部，实测按不到——**遥控器的焦点搜索出不了 `RecyclerView`**，
`FocusFinder` 找不到列表外的目标，DOWN 会直接落到 Activity 变成"无操作"。
放进列表后 UP/DOWN 必然可达，并且顺带把 OK 在分组行上的行为定义为"进入该分组的频道列"。

## 十四、设置页重做（统一风格）

**起因**：用户反馈设置页与整体风格不统一，需要重新设计。

**原状态**：系统默认控件拼出来的界面——Material 按钮 + `Switch` + 带下划线的 `EditText`，
和暗色选台面板完全是两种观感。

### 设计：统一到面板的视觉语言

| 元素 | 处理 |
|---|---|
| 面板背景 | 新增 `setting_panel_bg`（`#F510171C` + 1dp 描边 + 10dp 圆角），与选台面板同色系 |
| 分组小标题 | 绿色 `#8BC34A` 13sp：远程配置 / 显示与启动 / 数据源 |
| 可聚焦行 | 44dp，聚焦高亮**复用 `list_item_bg`**（与频道行完全一致） |
| 开关 | 行式「显示时间　开/关」，右侧状态文字（开=绿、关=灰），**替代系统 `Switch`** |
| 动作 | 「保存并重新加载」（绿色）/「恢复默认源」整行可点，**替代系统 `Button`** |
| 输入框 | 新增 `setting_input_bg`（暗色 + 聚焦时绿色描边），**替代系统下划线样式** |
| 标题 | 应用名 + 右侧绿色「设置」标签 |

样式统一定义在 `values/styles.xml`：`SettingSection` / `SettingRow` / `SettingLabel` / `SettingValue`。

### 顺带修掉的四个交互问题

1. **默认焦点落在第一个开关行**（原来是输入框，一进设置页就在编辑源地址）：`binding.rowTime.post { requestFocus() }`
2. **输入框吃掉方向键**：新布局漏了 `nextFocusDown/nextFocusUp`，补上后方向键可以走到下面的动作行
3. **去掉设置页 10 秒自动收起**：与面板保持一致，改为手动关闭（再按 MENU 或返回键）。
   同时删掉 `settingDelayHide` / `settingHideNow` / `settingNeverHide` / `hideSetting` / `delayHideSetting`（后两个已是死代码）与不再使用的 `handler` 字段
4. **修复「显示时间」开关不立即生效**：这条链路原先挂在 `settingDelayHide()` 里（它会顺带调 `showTime()`），
   随自动收起一并删除后就断了；现改为开关回调里直接调 `applySettings()`

### 验证结果

- 打开设置页 → 默认聚焦「显示时间」→ 按 OK：`关 → 开`，时钟立即出现（日志 `showTime true`）
- 受控单次按键测试：**一次 OK 只翻转一次**（日志仅一条 `showTime true`，SP 同步 `time=true`）
