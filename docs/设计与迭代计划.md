# 我的电视 —— 整体设计与迭代计划

> 本文是**战术文档**，服从 `docs/产品主旨与开发方向.md`（纲领：做什么 / 为谁做 / 坚持什么 / 不做什么 / 怎么算成功）。
> 目标：在「大道至简」的前提下，把**数据源与播放成功率**做到极致；不向用户抛堆功能与操作。
> 本文承接 `docs/借鉴计划.md`，是下一阶段的总体设计与排期。

---

## 一、设计原则

1. **默认零配置可用**：装完即有台（内置精选源），用户不填任何东西也能看。
2. **进阶走远程配置**：URL 输入、收藏管理等复杂操作全部搬到手机/电脑浏览器（`ConfigServer`），遥控器只负责看。
3. **自动决策优于开关**：软解、换台方向、信息显示等由程序判断，不再让用户选。
4. **信息收敛**：播放中的状态（线路切换、加载）合并进已有的信息条，只有"失败"才弹窗。
5. **数据源优先**：把工程预算投在缓存、探活、测速、排序上，而不是堆更多订阅地址。

## 二、目标架构

### 2.1 分层

```
┌─────────────────────────────────────────────┐
│ UI 层   MainActivity + Fragments（保持）      │
│         Player / List / Info / Channel /      │
│         Setting(瘦身) / Time / Error          │
├─────────────────────────────────────────────┤
│ 播放层   统一 Media3（移除 ExoPlayer2）        │
│         Renderer 自动降级：硬解失败→软解        │
├─────────────────────────────────────────────┤
│ 数据层   SourceManager（新增）                 │
│         fetch → parse → fold → probe →        │
│         rank → cache → render                 │
├─────────────────────────────────────────────┤
│ EPG 层   EpgStore：多源合并 + 缓存             │
├─────────────────────────────────────────────┤
│ 配置层   ConfigServer（主）+ SP（持久化）      │
└─────────────────────────────────────────────┘
```

### 2.2 核心变更：`TVList` → `SourceManager`

现状 `TVList` 是一个纯解析 `object`，每次冷启动全量网络拉取。演进为带状态的仓库：

| 能力 | 现状 | 目标 |
|---|---|---|
| 订阅拉取 | 每次冷启动全量拉 | 启动先读盘，后台刷新 |
| 本地缓存 | 无 | `filesDir/channels.json`（含时间戳） |
| 线路探活 | 无（播到才知道坏） | 后台并发探测，记录可达性+首包延迟 |
| 线路排序 | 仅 `isLoopSuspect` 粗排 | 探活+低延迟优先，坏线降权 |
| 解析格式 | m3u/txt/json | 保持 |
| 折叠 | `canonicalName` | 保持 |

数据流：

```
SP.iptvSourceUrl ──┐
                   ├─► fetch(多源+镜像) ─► parse ─► fold(同名折叠)
内置精选源 ────────┘                                   │
                                                       ▼
        ProbeManager(后台并发探活/测速) ─► rank(排序/降权)
                                                       │
                                                       ▼
                              channels.json(落盘) ─► 渲染频道列表
                                                       │
                                          启动时先渲染缓存，网络回来再 diff 刷新
```

## 三、关键模块设计

### 3.1 播放统一（Media3 单引擎）

- **移除** `com.google.android.exoplayer:exoplayer-*:2.13.3`，只保留 Media3 1.3.1。
- **天猫兼容**：不再用第二套播放器，改为在 `DefaultRenderersFactory` 上做 **自动降级**：
  1. 首次用默认（硬解）selector；
  2. `onPlayerError` 后，若该频道尚未软解试过，切 `softwareFirstSelector` 重试一次；
  3. 仍失败才走换线路逻辑。
- **收益**：APK 体积显著下降、重试逻辑只有一条路径、headers/源类型对天猫同样生效。
- **风险**：天猫真机需验证。保留一个隐藏开关（长按"关于"进入）作回退，而非设置页常驻。

### 3.2 数据源管线（SourceManager）

- **缓存**：`channels.json` 存 {组→频道[]}，另存探活结果与更新时间；启动即渲染。
- **探活**：空闲时对每条线路发探针（HEAD，失败再短超时 GET range），并发限流（如 8 路），记录 `ok + latencyMs + 时间`。
- **排序**：`已探活 && 低延迟` 优先；`isLoopSuspect` / 历史失败 降权到末位。
- **降权记忆**：本会话内播放失败的线路打标，不再优先选。
- **内置精选源**：内置一份长期稳定、社区维护的公开源，保证"装完就有台"。

### 3.3 收藏稳定性

- 收藏键当前为 `canonicalName(title)`，源变更后易失配。
- 改进：优先按 `tvg-id` 匹配 → 回退 `canonicalName` → 再回退模糊匹配；匹配失败时**保留收藏记录**而非丢弃，下次源出现再关联。

### 3.4 设置页减法

| 现状项 | 处置 |
|---|---|
| 换台反转 | 删除（固定默认行为） |
| 显示频道号 / 显示时间 | 合并为 1 个「显示信息」开关 |
| 软解优先 | 删除（改自动降级） |
| IPTV 文本框 + 保存 | 弱化，首屏主推远程配置地址/二维码 |
| 恢复默认 | 并入「关于」 |
| 退出 | 并入「关于」 |

目标：设置页 ≥ 3 项，首屏 = 远程配置入口 + 显示信息 + 关于。

### 3.5 交互收敛

- 线路切换 `Toast("线路 2/5")` 改为 `InfoFragment` 信息条展示。
- `recreate()` 刷新改为**内存重排 + 局部刷新**（收藏、换源、远程配置保存）。
- 首次启动引导页：一句"手机访问 http://<ip>:34567 可配置频道"，3 秒自动消失。

## 四、迭代计划

### 迭代 0：稳定性修复（P0，先止血）

| 任务 | 改动点 | 验收 |
|---|---|---|
| 修复离线不播放 | `MainActivity` 去掉 `ready==6` 魔法计数，改为「数据就绪」单一信号 | 飞行模式下内置源可正常起播 |
| 修复空监听器 | `Request.setRequestListener` 真正保存/回调，或删除该机制 | 无死代码调用 |
| 天猫路径补重试 | 随 3.1 一并解决 | 天猫设备可自动换线 |
| DNS 缓存加 TTL | `DnsCache` 60s 过期，失败清缓存重查 | CDN 换 IP 后自愈 |
| 去重逻辑修复 | `MainFragment.check()` 真正更新 `lastVideoUrl` | 重复起播被拦截 |
| EPG 线程安全 | `EpgStore.epgMap` 加 `@Volatile`/同步 | 无并发读写隐患 |

### 迭代 1：数据源极致化（核心）

| 任务 | 说明 |
|---|---|
| 频道列表缓存秒开 | `channels.json` + 启动先渲染 |
| 后台探活测速 | `ProbeManager` 并发探测 + 结果落盘 |
| 线路排序/降权 | 按探活与延迟排序，失败降权 |
| 内置精选源 | 内置稳定公开源做首次兜底 |
| EPG 多源合并 | 多 XMLTV 地址合并而非首个即停 |
| 远程配置"测试源" | 配置页加按钮，返回解析台数/分组数 |

**验收**：断网冷启动仍能出完整频道列表；坏线在选台前已被排到后面；首次安装无需配置即可观看。

### 迭代 2：减法与交互

| 任务 | 说明 |
|---|---|
| 设置页瘦身 | 按 3.4 精简到 ≤3 项 |
| 去 `recreate()` | 收藏/换源/配置改为局部刷新 |
| 提示收敛 | 线路切换进信息条，失败才弹窗 |
| 首次引导 | 远程配置引导页 |
| 收藏稳定性 | 按 3.3 改造匹配与保留策略 |

**验收**：用户首次上手只需"打开→看"；进阶用户全流程不用遥控器输入字符。

### 迭代 3：工程化

| 任务 | 说明 |
|---|---|
| 播放器统一收尾 | 删除 ExoPlayer2 依赖与死代码 |
| 体积优化 | 按 ABI 拆分 / 移除无用模块 |
| ConfigServer 加 token | 局域网配置加简单鉴权 |
| 平台适配器抽象 | `SourceAdapter` 接口，仅适配平台**公开**接口 |

## 五、明确不做 / 边界

> 本节已被 `docs/产品主旨与开发方向.md` 第 4.2 节细化：调用平台**公开但未文档化**接口取流属"灰色地带"（保留、仅限个人自用）；
> 硬红线是破解 DRM / 付费墙 / 订阅校验。两者冲突时以纲领文档为准。

- **不做**：破解 DRM、付费墙、订阅校验（即"逆向"）。需要鉴权的平台，仅支持用户**自带 token/cookie 透传**。
- **不做**：DIY 皮肤、多语言、账号体系等与"看电视"无关的功能。
- **不堆**：设置项、弹窗、需要用户理解的概念。

## 六、优先级总览

| 批次 | 主题 | 价值 |
|---|---|---|
| 迭代 0 | 稳定性修复 | 直接减少"打不开/不播" |
| 迭代 1 | 数据源极致化 | 体验质变（秒开、少坏线） |
| 迭代 2 | 减法与交互 | 契合大道至简 |
| 迭代 3 | 工程化 | 体积/维护成本 |

## 七、实施进度

- [x] **迭代 0 稳定性修复**：就绪信号改为 Fragment 集合（离线可播）、Request 监听器真实回调、天猫旧播放器补两级重试、DnsCache 60s TTL、列表去重修复、EpgStore 线程可见性
- [x] **迭代 1 数据源极致化**：`ChannelCache`（channels.json 落盘 + 失败回退链）、`ChannelProbe`（后台探活测速 + 排序降权）、EPG 多源合并、配置服务"测试源"接口、换源清缓存
- [x] **迭代 2 减法与交互**：设置页瘦身（移除换台反转、合并显示开关）、去 `recreate` 改原地重载（`MainFragment.reload()` 可重入列表 + 按频道名恢复位置）、提示收敛到信息条、首次启动远程配置引导、收藏模糊匹配
- [x] **迭代 3 工程化**：播放器统一为 Media3 单引擎（移除 ExoPlayer2 依赖与天猫专用 SurfaceView 分支），失败自动降级软解取代软解开关，ConfigServer 访问令牌鉴权，清理死代码（TVViewModel 冗余字段、`getAppSignature`、`isTmallDevice`、`NetworkChangeReceiver`、Ext 签名/网络扩展、Utils `TimeResponse`、无用字符串资源）
- [ ] **待补**：内置精选源（需经过验证的公开源地址，避免编造失效链接）

### 迭代 3 之后的补充
1. **缓存秒开已补齐**（原迭代 1 顺延项）：首帧先渲染本地缓存并起播，后台 `loadRemote()` 返回后按**结构指纹**比对，仅在结构变化时原地重建并保持当前频道；未配置远程源时直接用内置源，不回退历史缓存。
2. 软解开关在迭代 2 暂留、迭代 3 移除（自动降级落地后已无必要）。
3. **画质优先（方案 C）**：
   - 线路排序改为 `录像轮播末位 → 画质分降序 → 探活延迟升序`；
   - 画质分来自频道名/地址中的 `4K/2160/UHD`、`1440/2K`、`1080/FHD`、`720`、`576/480` 标签，`50/60FPS`、`HEVC/H265` 额外加分，按线路记录在 `TV.urlQuality`；
   - 播放器默认 `setForceHighestSupportedBitrate(true)` 拉满画质；播放中 30s 内出现 3 次以上缓冲即判定弱网，自动放宽（解除强制 + 限制码率 2 Mbps）并信息条提示，本会话只降一次。
4. **线路列表（`SourceFragment`）**：播放中**长按左/右键**弹出当前频道的线路列表，标注「画质 · 延迟 · 疑似录像 · 域名」，当前线路置顶聚焦；OK 切换、返回键关闭。短按左右键仍为循环切换（改为在 `onKeyUp` 执行，避免长按先误切一次）。

### 迭代 3 的两处刻意不做
1. **`SourceAdapter` 抽象**：当前只有凤凰卫视一个平台适配器，为单一实现引入接口属于过度设计，违背"大道至简"。待第二个平台适配真正落地时再抽取。
2. **未开启 R8 / 资源压缩**：需要保 Gson/Retrofit 反射模型的 keep 规则并做 release 真机验证，在无法运行时验证的前提下开启会有"静默坏包"风险，留待有条件时再启用。
