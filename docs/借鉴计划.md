## 二、借鉴清单（按迭代批次）

### 迭代一：播放成功率与选台（P0，全部小工作量）

**1. 两级重试轮换（源类型 → 线路）**
- 借鉴：`my-tv-0/app/.../TVModel.kt` 的 `sourceTypeList` 设计
- 设计：按 URL 后缀/scheme 生成候选类型（m3u8→HLS；mpd→DASH；rtsp/rtmp→各自；其余→[HLS, PROGRESSIVE]）。
  播放失败先 `nextSourceType()`（不计入重试上限），类型穷尽再 `nextVideo()` 换线路并清零计数；
  成功后把确认的类型/线路下标持久化到 TV，下次直接从成功处开始。
- 改动点：`TV.kt`（+confirmSourceType/confirmVideoIndex 字段）、`PlayerFragment.onPlayerError`
- 工作量：小

**2. tvg-chno 数字选台**
- 借鉴：`MainViewModel.str2Channels` L444（解析）+ `ChannelFragment` L76-143（选台）
- 设计：解析 `tvg-chno="N"` 存入 `TV.chno`；数字键逐位拼接、5 秒超时或满 3 位触发；
  选台先按 chno 精确匹配，无匹配再按列表序号；显示号 = chno>0 ? chno : id+1
- 改动点：`TV.kt`、`TVList.kt`（解析）、`ChannelFragment.kt`（匹配逻辑）、`MainActivity.onKeyDown`
- 工作量：小

**3. GitHub 镜像加速**
- 借鉴：`Utils.getUrls()`（13 个镜像前缀，raw.githubusercontent.com/github.com 链接自动展开）
- 设计：`TVList.fetch()` 拉取订阅失败时自动逐个尝试镜像前缀；配置页写原始 GitHub 地址即可
- 工作量：小（一个纯函数 + fetch 循环）

**4. 网络时间校准多源化**
- 借鉴：多地址逐试（我们当前只有淘宝单一来源，失败即弃）
- 设计：时间源列表 [淘宝, ip.ddnspod.com/timestamp,苏宁] 逐试，全部失败才回退设备时钟
- 工作量：小

### 迭代二：远程配置与源能力增强（P1）

**5. 内置 HTTP 配置服务**
- 借鉴：`SimpleServer.kt`（NanoHTTPD 2.3.1，端口 34567）+ `res/raw/index.html`
- 设计：GET `/` 配置页（订阅源地址、收藏列表两个编辑框）→ POST `/api/save` 写 SP → 提示重启；
  GET `/api/config` 返回当前配置 JSON。设置页显示 `http://<局域网IP>:34567` 入口文字
- 依赖：`org.nanohttpd:nanohttpd:2.3.1`；启动挂 `MyApplication.onCreate`，`onDestroy` 停止
- 工作量：中（页面 UI + 生命周期）

**6. #EXTVLCOPT headers 透传**
- 借鉴：`str2Channels` L447-458（`#EXTVLCOPT:http-user-agent=xxx` → `tv.headers`）
- 设计：`TV.kt` + `headers: Map<String,String>`；`PlayerFragment` 的 DataSource 工厂
  `setDefaultRequestProperties(headers)`；UA 单独取出供 RTSP
- 工作量：小

**7. json 源格式**
- 借鉴：`TV.kt` 即 json schema（name/title/logo/uris/headers/group/number）
- 设计：`TVList` 按首字符分派（`[` → json）；Gson 直接映射
- 工作量：小

**8. EPG 节目单（XMLTV）**
- 借鉴：`EPGXmlParser.kt` + `updateEPG` 多地址轮试 + filesDir 缓存 + 模糊匹配
- 设计：m3u 头 `x-tvg-url` 优先、设置项兜底；解析 `<channel>`/`<programme>`；
  过滤已结束节目；结果 JSON 缓存到 filesDir；InfoFragment 显示"当前/下一个"节目
- 工作量：小-中

**9. 频道 LOGO 缓存与兜底**
- 借鉴：`ImageHelper.kt`（logo 落盘 cacheDir/logo/{频道名}，多 URL 备选，fanmingming 兜底）
- 设计：CardPresenter 加载前先查本地缓存；tvg-logo 为空时用 `live.fanmingming.cn/tv/{tvg-name}.png`
- 工作量：小

### 迭代三：兼容性与工程化（P2，可选）

**10. 软解开关 + H265 强制软解**
- 借鉴：`PlayerMediaCodecSelector`（H265 强制 c2.android.hevc.decoder）+ ffmpeg 解码 aar
- 设计：设置项"软解码"；引入 `lib-decoder-ffmpeg-release.aar`（解决 audio/mpeg-L2 无声）
- 工作量：中（aar 体积 +60MB 左右，考虑按 ABI 拆分）

**11. 崩溃上报（限次防循环）**
- 设计：自建 or 关闭上报端点（**不抄 lyrics.run 依赖**）；`isLimit()` 每版本限 10 次的细节保留
- 工作量：小（若上报到自建服务）／跳过

**12. 恢复默认设置**
- 借鉴：SettingFragment 一次性重置 SP + 清缓存文件
- 工作量：小

## 三、明确不借鉴

- Gua64 六十四卦源编码混淆（防抓取需求，与我们无关）
- 强制繁体 locale
- 洋葱式 ISP 识别内置源（半成品）
- lyrics.run 相关的所有服务依赖

## 四、迭代节奏建议

1. **第一周**：迭代一全量（1-4）—— 播放成功率和镜像容错立竿见影
2. **第二周**：迭代二 5-7（远程配置解放遥控器输入，json/EXTVLCOPT 补齐解析器）
3. **第三周**：迭代二 8-9（EPG + logo），随后视需求进入迭代三
